## GitHub-native achievements

GitHub awards profile achievements automatically; they cannot be legitimately added as decorative stickers. Use the **[official achievement shelf](https://github.com/Kishordiu?tab=achievements)** to see which ones your account has earned. This README uses real workflow-status badges and technology badges separately.

Milestones worth pursuing through genuine community work:

- **Pull Shark** — earn it by getting meaningful pull requests merged; the first level starts at two.
- **Galaxy Brain** — contribute useful answers in public repositories' Discussions and have two accepted.
- **Pair Extraordinaire** — collaborate on a real change and get a co-authored pull request merged.
- **Starstruck** — grow one of your own public projects to 16 stars.

These thresholds are community-documented and can change; GitHub itself decides when an achievement is awarded. I won't display an achievement as earned until it appears in the native shelf.

## The F.O.R.G.E. README protocol

Every project should feel like its own product—not a copy-pasted page. The portfolio's README method is **Form → Objective → Route → Ground truth → Execute**: distinctive artwork, a clear purpose, a legible system path, honest implementation boundaries, and commands that match the source.

[Read the F.O.R.G.E. protocol and its quality gate](https://github.com/Kishordiu/Kishordiu/blob/main/FORGE_README_PROTOCOL.md).

## The working principle

> Don't just make the interface look finished. Make the system make sense.

```text
QUESTION → RESEARCH → DESIGN → BUILD → TEST → ITERATE → SHIP
```

The public portfolio contains products, technical prototypes, and experiments at different stages. Each project README should make the implemented functionality and future direction clear.
